# Security Policy

LLM Gateway is a self-hosted proxy that stores your LLM provider API keys
(`.env`), a Postgres password, a session secret, and a LiteLLM master key.
Please take vulnerability reports seriously — many issues here have outsized
security impact compared to typical web apps.

## Supported Versions

| Version | Supported |
|---------|-----------|
| 1.1.x   | ✅        |
| < 1.1.0 | ❌        |

## Reporting a Vulnerability

**Do NOT open a public GitHub issue for security reports.**

Use GitHub's private vulnerability reporting:
**Security → Report a vulnerability** at
https://github.com/vijaytank/llm-gateway/security/advisories/new

Include: affected component (`gateway/`, `adapter/`, `ui/`, `brain/`,
`wizard/`), reproduction steps, and impact assessment. You'll get an initial
response within 7 days.

## Known Design Notes (not vulnerabilities, but read before reporting)

- Provider API keys never appear in `gateway_config.yaml` — only the
  *env-var name* is stored (`api_key_env`). If you find a key value written
  into config, that IS a bug worth reporting.
- The web UI (port 4002) uses bcrypt-hashed admin credentials stored in
  Postgres and signed cookies (24 h expiry). There is deliberately no TLS
  termination inside the stack — put it behind your reverse proxy.
- The LiteLLM proxy (4000) and adapter (4001) authenticate with
  `LITELLM_MASTER_KEY`. Do not expose these ports publicly without that key
  set (≥ 32 random chars, generated by `python wizard/setup.py`).
- **CSRF posture:** All state-mutating POST routes in the web UI rely on
  `SameSite=Lax` session cookies as the primary CSRF defence. This is
  sufficient for modern browsers but does not include explicit CSRF tokens.
  Adding `itsdangerous`-signed tokens to all forms is planned as a
  defence-in-depth measure in a future release. Do not file this as a
  vulnerability unless you have a working PoC that bypasses `SameSite=Lax`
  in a supported browser.
